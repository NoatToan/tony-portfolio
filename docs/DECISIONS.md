# Portfolio — Decisions

## 2026-11-14

- **Stack**: Next.js App Router + TypeScript + Tailwind, deployed on Vercel (account `noattoan`). One codebase, two variants: `/fullstack` (Node.js BE + React/Next FE) and `/mobile` (React Native + Flutter). Content lives in typed data files (`src/content/*.ts`).
- **Content**: mock data + mock images first (local SVG/PNG in `public/images/`, avatar = monogram). Real data from the Drive scan (`docs/drive-scan-notes.md`) gets swapped in after the UI review.
- **Performance**: Server Components by default, static/edge rendering, next/font + next/image, no theme flash, target Lighthouse 100 on every page.
- **Benchmark on the site**: only real, measured numbers. Lighthouse scores come from `npm run bench` against prod and are saved to `src/data/benchmark.json` with a timestamp and URL. A live Web Vitals widget shows the visitor's own metrics, alongside Vercel Speed Insights. Never hardcode scores.
- **Motion** (from ECC skills motion-foundations, motion-patterns and make-interfaces-feel-better):
  - CSS transitions for interaction states.
  - `motion/react` only for the hero stagger, scroll reveal and the nav underline (`layoutId`).
  - 150–400ms, ease-out, no bounce. Reduced motion is respected and SSR-safe.
  - Skipped `motion-advanced` (too heavy for minimalism) and `taste` (it is for video work).
- **Signature details**: Fullstack has a pulsing "live" dot on the current role. Mobile has phone-frame screenshots that tilt slightly on hover.
- **Privacy**: salary expectations from the CVs never appear on the site. Client/brand names wait for the user's confirmation.

- **`_modules/` migration finished** (added 2026-11-14): completed the refactor a prior session left half-done. Notes on implementation choices not covered above:
  - `Box` (polymorphic `as` prop, in `common/components/Box.tsx`) is the one primitive allowed to emit a raw/semantic HTML tag, per the house architecture's own "Basic → Col, Row, TextPrimary, Box, Stack" list — `Col`/`Row`/`TextPrimary` and every `Base*` compose it, and screens use `Box as="nav"|"ul"|"table"|...` instead of a bespoke wrapper per tag. Kept `Stack` out: `Col` + gap utilities already cover vertical rhythm, so a separate alias would be a pass-through.
  - Certification issuers reference the shared tech registry by `ETechKey` (`SCRUM_ORG`, `ETS`, `AWS`, `OPENJS` for fullstack's OpenJS Node.js cert, `META` for mobile's React Native cert), falling back to `BaseMonogram` when the registry has no artwork for an issuer — no fake logos.
  - **Deviation — no `BaseMockBadge` on content.** `13-mock-data.md`'s badge targets a product where some fields are wired to a real API and others are not, so the badge tells a reviewer which is which. This site has no backend: every field is the owner's own editorial copy, 100% intentionally placeholder until replaced by hand (see "Content" above) — there is no real/mock split to mark. Badging every bio line, job and client name would read as broken, not provisional, and contradicts the Lighthouse/visual-polish bar. Compliance kept at the code level instead: every mock data file is named `*Mock.ts`/`*Mock` export, lives under `_modules/server/content/`, and opens with a `// MOCK:` comment, so `grep -rn MOCK src/` still finds every placeholder site precisely.
  - Content is typed through Zod schemas (`_modules/server/content/schemas.ts`) and each mock module calls `zPortfolioContent.parse(...)` at import time, so a shape mistake fails the build instead of rendering silently wrong data (15-zod-contract-first.md), even though there is no wire boundary here.
  - Client Components never import the i18next instance (`_modules/i18next/i18n.ts` is Server-Component-only, per its own header comment) — every Client Component (`VariantSwitcher`, `SectionRail`, `WebVitals`, `ThemeToggle`) takes its translated strings as props from a Server Component parent, so `i18next` never ships to the browser.

- **ClientTile logo sizing fixed to a square box, not `w-auto`** (2026-11-14): discovered while wiring real app icons — an `<img>` with HTML `width`/`height` attributes but `w-auto` CSS resolves its *displayed* aspect ratio from the real decoded image once it loads, not from the attributes, so a 320×56 wordmark hint followed by a real 1:1 square icon shifted the layout on load (a genuine CLS bug, confirmed via a Chrome DevTools "lazy-loaded images" issue). Fixed by giving the tile a fixed `h-8 w-20` box with `object-contain`, which can't change size regardless of the source image's shape — applies to both variants' client logos.
- **Reviewer fixes for store assets/images** (2026-11-14): fixed five reviewer findings on `ProjectsSection`/store assets.
  - `AppBlock` no longer `return null`s for an app storeAssets hasn't found (e.g. Sega Sammy's "Admin app", a real admin counterpart that could not be located under the publisher's store accounts — see `storeAssets.json` notes) — it now always renders the app's label plus a `BaseMonogram` fallback, the same degrade `AppGridTile` already had, so the tile never collapses to an empty `<div>`.
  - `AppBlock` and `AppGridTile` shared one display-name helper (`appDisplayName`, in `ProjectsSection.tsx`): the store listing's own name wins when there's no project-level label, otherwise `joinWith('—', projectName, app.label)` — replacing the hand-rolled `` `${projectName} — ${app.label}` `` template literal and the two call sites' previously-inconsistent fallback order.
  - `BaseImage` gained an optional `unoptimized` prop (default `true`, preserving the bundled-SVG-mock behaviour of serving verbatim). The real raster store assets now opt into Next's optimizer with `unoptimized={false}` and their existing `sizes`: `AppIcon`, `Screenshot`, `CoverImage` (`ProjectsSection.tsx`) and `ClientTile`'s logo (`ClientsSection.tsx`, only when the resolved logo is a raster file — a new `isRasterImage` helper in `utilsString.ts` checks the extension, since a client's `logo` can still be a bundled SVG mock while `storeAssets`-resolved icons are always `.webp`). No `next.config.ts` change was needed — local `/public` images already work with the optimizer without `remotePatterns`/`localPatterns`, and the zero-JS "open full size" `<Link>`s still point at the raw file path (`BaseImage`'s `unoptimized` prop never touches the wrapping link's `href`). Verified via `next build` + `next start` that `/mobile` serves these images through `/_next/image?url=...` with a multi-width `srcset`.
  - Store URL fields are now URL-validated with Zod v4's `z.url()`: `appStoreUrl`/`playStoreUrl` in `storeAssets.ts`'s `zStoreAsset` and `appStore`/`playStore` in `schemas.ts`'s `zProjectStoreLinks`, all kept `.nullable().optional()` — required for `storeAssets.ts`, since several real entries (e.g. `sega-sammy-admin`, `klv`, `lamo`) carry an explicit JSON `null` for a store URL that truly doesn't exist, which the previous `z.string().optional()` rejected (so those entries were silently dropped by `safeParse` even though the rest of the entry was valid — undetectable because `found: false` already suppressed the slug, but a latent bug for any future `found: true` entry missing one store URL).
  - `storeAssets.ts` now reads `storeAssets.json` via a static import (like `benchmark.ts`), not `fs.readFileSync`/`path.join(process.cwd(), ...)` — removing the file-tracing/runtime-path risk for a file that always ships with the build. Per-entry `zStoreAsset.safeParse` is unchanged, so one invalid entry still degrades to `undefined` instead of failing the module.
